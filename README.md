# KadrRoom

KadrRoom — приложение для совместного просмотра фильмов и прослушивания музыки. В комнате до пяти человек. Ведущий выбирает медиа из серверного каталога и управляет общим плеером. Участники могут говорить и включать камеры. Владелец каталога загружает и публикует файлы через админку.

## Что уже есть

В браузере доступны каталог, регистрация с подтверждением почты, вход и восстановление пароля. Ведущий создаёт комнату из каталога и делится ссылкой. Гость подключается по приглашению. Комната синхронизирует воспроизведение по WebSocket, а LiveKit передаёт звук и видео с камеры. Оператор управляет загрузкой, обработкой и публикацией медиа из отдельной админки.

## Локальный запуск

Для полного запуска нужны Docker и Docker Compose. Все команды выполняются из корня проекта.

```sh
bash tools/local/stack.sh testing up -d --build
bash tools/local/stack.sh prod up -d --build
```

| Окружение       | Сайт                                    | Админка                                 | Тестовая почта                          |
| --------------- | --------------------------------------- | --------------------------------------- | --------------------------------------- |
| `testing`       | [127.0.0.1:4173](http://127.0.0.1:4173) | [127.0.0.1:4183](http://127.0.0.1:4183) | [127.0.0.1:8025](http://127.0.0.1:8025) |
| `prod` локально | [localhost:4174](http://localhost:4174) | [localhost:4184](http://localhost:4184) | [localhost:8026](http://localhost:8026) |

Оба профиля предназначены для локальной проверки по HTTP. У каждого свои базы PostgreSQL, тома медиа, конфигурация и тестовая почта Mailpit. Для входа в админку зарегистрируй `operator@example.test` на сайте нужного окружения и подтверди адрес по письму из его Mailpit. Локальные параметры и автоматически созданные секреты остаются в `.env.testing.local` и `.env.prod.local`.

Состояние контейнеров показывает `bash tools/local/stack.sh testing ps -a`. Остановить окружение с сохранением данных можно через `bash tools/local/stack.sh testing stop`. Для второго окружения используй `prod`.

### Быстрый запуск каталога для разработки

Нужны Go 1.26 и Node.js 22 от 22.22.3, 24 от 24.15.0 или 26. Для линтинга Go используй `golangci-lint` v2 с поддержкой Go 1.26. Установи зависимости npm-workspace.

```sh
npm ci
```

В одном терминале запусти API.

```sh
go run ./apps/catalog-api
```

Проверь API напрямую.

```sh
curl http://127.0.0.1:8080/healthz
curl http://127.0.0.1:8080/readyz
curl http://127.0.0.1:8080/v1/catalog
```

В другом терминале запусти Angular.

```sh
npm run dev
```

Открой `http://127.0.0.1:5173`. Angular CLI отправляет запросы `/v1/` на Go API.

`npm run build` и `npm run build:admin` собирают два Angular-приложения и проверяют их шаблоны.

## Проверки

| Команда                | Назначение                                                                  |
| ---------------------- | --------------------------------------------------------------------------- |
| `npm run format`       | Форматирует исходники и конфигурацию через Prettier и gofmt                 |
| `npm run format:check` | Проверяет форматирование                                                    |
| `npm run lint`         | Запускает ESLint со строгими правилами TypeScript и Angular и golangci-lint |
| `npm run typecheck`    | Проверяет типы приложения, тестов и пакета контрактов                       |
| `npm test`             | Запускает юнит-тесты и тесты HTTP, проверяет гонки и измеряет покрытие      |
| `npm run check`        | Проверяет формат, линтеры, типы, юнит-тесты и сборку                        |
| `npm run test:e2e`     | Проверяет каталог Playwright в Chromium, Firefox и WebKit                   |

Перед первым запуском Playwright установи браузеры командой `npx playwright install`.

`npm run test:unit:frontend` требует 100% покрытия схемы каталога, разбора ответа и форматирования длительности.

Сквозные тесты проверяют подтверждение почты и сброс пароля, гостевой вход, синхронизацию воспроизведения, публикацию и звонок через запущенное окружение `testing`.

```sh
export KADRROOM_E2E_BASE_URL=http://127.0.0.1:4173
export KADRROOM_E2E_ADMIN_URL=http://127.0.0.1:4183
export KADRROOM_E2E_MAIL_URL=http://127.0.0.1:8025
bash tools/ci/wait-testing-stack.sh "$KADRROOM_E2E_BASE_URL" "$KADRROOM_E2E_MAIL_URL" "$KADRROOM_E2E_ADMIN_URL"
npm run test:e2e -- web-flow.spec.ts account-recovery.spec.ts
KADRROOM_E2E_RTC=1 npm run test:e2e -- --project=chromium admin-flow.spec.ts rtc-flow.spec.ts
```

## CI и тестовый деплой

У приложений отдельные workflow с фильтрами по коду и зависимостям. Для полного прогона выбери `CI` → `Run workflow` в GitHub Actions. Он проверяет конфигурацию CI, запускает линтинг, проверки типов, юнит-тесты, Go-тесты с детектором гонок и сборки. Все браузерные проверки выполняются в одной джобе Playwright.

BuildKit собирает семь образов в kind. CI запускает сквозные тесты через Compose из архивов этой сборки. Полный тестовый деплой в отдельный kind проверяет все семь образов и маршруты между сервисами. Дополнительные проверки каталога и фронтенда подтверждают восстановление после отключения API и замену подов. При сбое Actions сохраняет диагностику окружения и отчёт Playwright.

Выкладка на VPS запускается вручную отдельным workflow после полного CI. Манифесты K3s, требования к окружению и порядок проверки описаны в [документации развёртывания](deploy/k8s/README.md).

## Общие контракты

`@kadrroom/contracts` в `packages/contracts/` содержит общие TypeScript-типы. При изменении публичного контракта обнови версию пакета и зависимость приложения, затем проверь совместимость. Тег `contracts-v<версия>` создаёт GitHub Release с npm-архивом пакета. Версия в теге должна совпасть с `packages/contracts/package.json`.
